01

이 템플릿으로 만드는 것#

예제는 스티키 노트입니다. 캔버스 도구 선반에 추가 버튼을 제공하고, 노트의 제목·메모·배경색을 속성 패널에서 편집합니다. 생성과 속성 편집은 호스트의 단일 Undo 타임라인을 사용하며, 설치나 화면 열람만으로 문서를 만들지 않습니다.

extension.jsonID · 버전 · 요약 · 의존성
→
src/manifest.js런타임·빌드 공용 계약
→
src/index.js어스펙트 · UI · activate
→
dist/plugin.js기본 export 1개
→
GitHub 설치alid.extension.json + SHA-256
한 방향으로만 흐르는 계약 생성 산출물은 직접 편집하지 않는다
세 가지 경계

저장소 — 앱·커널과 분리된 독립 GitHub 저장소. 별도 웹 호스팅·npm 배포가 필요 없습니다.

실행 — 사용자가 승인한 뒤 앱 안에서 실행되는 신뢰 확장입니다. 샌드박스가 아닙니다.

데이터 — 문서에는 사용자 의도만 저장합니다. 파생 기하·DOM 측정·타이머·Blob URL은 정본이 아닙니다.

새 확장을 만들 때만 example.sticky-notes를 고유 네임스페이스로 바꿉니다. 기존 확장을 업데이트할 때는 ID와 어스펙트 ID를 유지하고 version만 올립니다. 이 저장소의 공개 설치본과 내 저장소를 동시에 설치하려면 먼저 ID를 바꿔야 합니다.

02

5분 안에 시작하기#

Node.js 22.12 이상과 package.json에 고정된 pnpm 11.22.0을 사용합니다. 이 저장소에는 별도 typecheck나 Rust 테스트 명령이 없습니다. 존재하지 않는 명령을 완료 검증으로 보고하지 마세요.

shterminal
pnpm install --frozen-lockfile
pnpm test          # 배포 번들을 빌드한 뒤 모든 Node 계약 테스트 실행
pnpm check:dist    # 재빌드 후 커밋된 산출물과 차이가 없는지 확인

pnpm dev           # watch 빌드 + http://127.0.0.1:5174
pnpm test:watch    # 별도 터미널에서 plugin/manifest 테스트 watch
  1. 저장소 만들기

    이 저장소에서 Use this template → Create a new repository를 선택하고 공개 저장소를 만듭니다.

  2. ID와 메타데이터 바꾸기

    extension.json의 id, title, version, summary를 수정합니다. id에는 yourname.reading-notes처럼 고유한 네임스페이스를 사용합니다.

  3. 연결하고 수정하기

    pnpm dev가 표시한 주소를 alid의 확장 관리 → 개발 중인 확장 연결에 입력하고 승인합니다. src/index.js를 저장하면 캔버스에 바로 반영됩니다.

  4. 빌드 산출물 커밋

    마무리 전에 pnpm test를 실행하고, 소스와 함께 dist/plugin.js, alid.extension.json, pnpm-lock.yaml을 커밋합니다.

API 2만 지원

engine: "^0.1.0"은 커널 호환 범위이고, 설치 형식은 apiVersion: 2입니다. 둘은 별개이므로 커널 버전만 보고 설치 가능 여부를 판단하지 마세요. API 1 매니페스트와 캐시는 실행 전에 거부되며 자동 변환되지 않습니다.

어스펙트나 명령을 추가·변경하면 런타임만 고치지 말고 공통 계약, 설치 메타데이터, 테스트, API 안내를 함께 확인합니다. 현재 extension.json의 provides에는 services와 hsmSlots만 허용되고, 어스펙트는 src/manifest.js가 provides.aspects로 생성합니다.

생성 산출물을 손으로 고치지 않습니다

dist/plugin.js와 alid.extension.json은 같은 빌드에서 함께 생성되어야 합니다. SHA-256을 수동으로 적거나 해시 검사를 끄면 설치가 거부되거나 검토한 코드와 실행 코드가 달라집니다.

04

패키지 계약#

번들의 기본 export는 ExtensionPackageSpec 형태의 객체 하나입니다. 필수는 id, version, summary이고, aspects, ui, activate는 기능에 따라 생략할 수 있습니다.

jssrc/index.js (구조)
export default {
  ...createPackageManifest(metadata),  // id·version·engine·의존성·provides
  summary: metadata.summary,

  aspects: [note],
  ui: { controls: [createButton] },

  activate(context) {
    // 명령·서비스·이벤트를 등록하고 정리 함수를 반환한다.
    return () => {};
  },
};
필드의미주의
id설치 단위의 논리 확장 ID점 포함. 새 확장에서만 변경
version확장 릴리스 버전MAJOR.MINOR.PATCH 정식 릴리스
engine커널 호환 범위설치 API 버전과 별개
summary확장 관리·검토 화면의 한 줄 설명설치 명세와 일치
dependencies필수 공급자키는 npm 이름이 아니라 alid 논리 확장 ID
optionalDependencies선택 공급자없어도 소비자가 동작해야 함
conflicts동시에 켤 수 없는 확장 ID빈 배열도 명시
providesservices, aspects, hsmSlots소유·제공 계약. 접근 의도와 다름

activate는 undefined, 정리 함수, 또는 { api, dispose }를 반환합니다. dispose는 비활성화·일시정지· 다시 불러오기·제거 시 호출됩니다. 여러 자원을 만들었다면 생성의 역순으로 정리하고, 이전 활성화에서 폐기한 자원을 다음 활성화에서 재사용하지 않습니다.

05

설치 명세#

호스트는 공개 GitHub 저장소의 기본 브랜치를 커밋 SHA로 고정한 뒤, 같은 커밋에서 alid.extension.json과 번들을 읽습니다. 아래는 스티키 노트 기준의 생성 예시이며, 실제 파일은 pnpm build가 만듭니다.

jsonalid.extension.json
{
  "apiVersion": 2,
  "id": "example.sticky-notes",
  "title": "스티키 노트",
  "version": "0.3.0",
  "engine": "^0.1.0",
  "dependencies": {},
  "optionalDependencies": {},
  "conflicts": [],
  "provides": {
    "services": [],
    "aspects": ["example.sticky-notes.note"],
    "hsmSlots": []
  },
  "summary": "캔버스에 짧은 메모를 추가하고 내용과 색상을 편집합니다.",
  "entry": "dist/plugin.js",
  "sha256": "빌드 시 생성되는 64자리 SHA-256",
  "aspectIds": ["example.sticky-notes.note"],
  "capabilities": {
    "readAspects": [
      "example.sticky-notes.note", "core.transform", "core.bounds"
    ],
    "writeAspects": [
      "example.sticky-notes.note", "core.transform", "core.bounds"
    ],
    "services": ["canvas.creation"],
    "commands": ["example.sticky-notes:add-note"]
  }
}

capabilities는 접근 의도를 설명합니다. 접근을 허가하거나 코드 전체를 격리하는 권한 목록이 아닙니다. dependencies·provides는 서비스와 공개 API의 의존성 검증에 사용됩니다.

설치 명세와 번들은 같은 빌드에서

id, version, engine, 두 의존성 맵, conflicts, provides는 번들의 값과 정확히 일치해야 합니다. src/manifest.js가 두 경로의 공통 값을 만들므로 생성 파일에 따로 적지 마세요.

06

객체 어스펙트#

어스펙트는 문서에 저장할 속성과 읽기 전용 파생·표시 동작을 정의합니다. 스티키 노트의 어스펙트 ID는 ${metadata.id}.note이며, ID를 바꾸면 기존 문서와의 호환성이 끊깁니다.

jssrc/index.js (어스펙트)
const aspectId = `${metadata.id}.note`;
const defaults = {
  title: '작은 생각',
  body: '이 메모를 선택하고 속성에서 내용을 바꿔 보세요.',
  color: '#f5f3ff',
};

function derive(_props, id, view) {
  const transform = view.getCanonical(id, 'core.transform') ?? {};
  const bounds = view.getCanonical(id, 'core.bounds') ?? {};
  return {
    x: finite(transform.x, 0),
    y: finite(transform.y, 0),
    width: positive(bounds.width, 240),
    height: positive(bounds.height, 160),
    rotation: finite(transform.rotation, 0),
  };
}

const note = {
  id: aspectId,
  label: '스티키 노트',
  summary: metadata.summary,
  defaults,
  textFields: ['title', 'body'],
  textSearchFields: ['title', 'body'],
  dependsOnCanonical: [aspectId, 'core.transform', 'core.bounds'],
  dependsOnComputed: [],
  derive,

  renderDom(content, props, geometry) {
    // 호스트가 준 콘텐츠 컨테이너만 소유한다. 외곽 좌표·회전은 호스트 몫.
    if (!geometry) return;
    content.innerHTML = `<svg ...>${noteBody(props, geometry)}</svg>`;
  },

  renderSvg(props, geometry) {
    if (!geometry) return { svg: '' };
    const { x, y, width, height, rotation } = geometry;
    return {
      svg: `<g transform="translate(${x},${y}) rotate(${rotation * 180 / Math.PI},${width / 2},${height / 2})">`
        + noteBody(props, geometry) + '</g>',
    };
  },
};
필드의미
defaultsJSON으로 저장 가능한 속성 기본값
textFields협업 텍스트로 취급하는 defaults 필드
textSearchFields검색 대상 텍스트 필드
dependsOnCanonical파생 계산이 읽는 정본 어스펙트 목록
derive()정본을 읽어 화면용 기하를 반환하는 순수 함수
renderDom()호스트가 준 콘텐츠 컨테이너에 표시
renderSvg(){ svg: 문자열 } 반환. 그리기 순서는 호스트가 결정
layouttrue면 파생 결과가 공용 레이아웃 박스 (자동 크기)
paintBounds()박스 없는 객체가 그리는 월드 박스
저장하지 않는 것

파생 좌표·DOM 측정값·함수·DOM 노드·타이머·Blob URL·카메라·선택·패널 상태는 정본이 아닙니다. derive 안에서 문서를 쓰거나 DOM·네트워크에 접근하지 마세요. 누락·잘못된 숫자에는 유한하고 결정론적인 기하를 반환합니다.

회전은 라디안입니다. 사용자 문자열은 DOM/SVG 삽입 시 이스케이프하고, 색상 값도 검증합니다. 원문을 innerHTML이나 SVG 속성에 그대로 넣지 마세요. 그리기 순서는 호스트의 단일 Z축(core.stacking)이 소유하며, 확장은 zOrder·layer를 반환하지 않습니다.

07

UI 기여#

생성 버튼은 설치 단위의 ui.controls에 tool-shelf action으로 기여합니다. 속성 컨트롤은 어스펙트의 ui.controls에 두고, field는 그 어스펙트의 defaults에 존재하는 속성을 가리킵니다.

js설치 단위의 도구 선반 버튼
ui: {
  controls: [{
    id: 'add-note',
    kind: 'action',
    label: '스티키 노트 추가',
    icon: 'document',
    commandSymbol: 'example.sticky-notes:add-note',
    placement: 'tool-shelf',
    requiresSelection: false,
  }],
}
js어스펙트의 속성 컨트롤
ui: {
  controls: [
    { id: 'note-title', kind: 'text',  field: 'title', label: '제목',   placement: 'inspector' },
    { id: 'note-body',  kind: 'text',  field: 'body',  label: '메모',   placement: 'inspector' },
    { id: 'note-color', kind: 'color', field: 'color', label: '배경색', placement: 'inspector' },
  ],
}
종류필드설명
textfield한 줄 텍스트
number, sliderfield, min, max, step수치 편집
colorfieldCSS 색상 값
togglefield불리언
segmentedfield, options선택지
actioncommandSymbol명령 실행. 선택 요구·활성 도구 상태 선언 가능

commandSymbol은 등록한 명령 ID와 같아야 합니다. 선택 없이 생성해야 하면 requiresSelection: false를 선언합니다. 호스트의 툴바·인스펙터 DOM을 직접 수정하지 마세요. 호스트가 선택된 객체의 필드를 읽고 편집·Undo를 처리합니다.

08

생성과 명령#

객체 생성은 canvas.creation 호스트 서비스로 합니다. 서비스가 없으면 이 기능을 제공하지 않는 호스트이므로 명확한 오류를 반환합니다. core.transform·core.bounds는 호스트가 작성하므로 aspects에 중복 전달하지 않습니다.

js생성 커맨드
const creation = context.services.get('canvas.creation');
if (!creation) throw new Error('canvas.creation 서비스가 필요합니다.');

return context.commands.register({
  id: 'example.sticky-notes:add-note',
  title: '스티키 노트 추가',
  summary: '현재 화면에 메모를 추가합니다.',
  shortcutScope: 'canvas',
  run: () => creation.create({
    caller: 'example.sticky-notes:add-note',
    aspects: { 'example.sticky-notes.note': { ...defaults } },
    width: 240,
    height: 160,
  }),
});

creation.create는 생성된 엔티티 ID를 반환하고, 내용·위치·크기를 한 정본 배치와 한 Undo 단위로 기록합니다. width와 height는 유한한 양수여야 합니다. 명령 ID는 namespace:name 형식이며 제목·설명· 실행 콜백이 필요합니다.

설치와 생성은 분리

설치·활성화·API 조회·화면 열람만으로 문서 객체를 만들지 않습니다. 쓰기는 사용자의 명시적인 명령이나 속성 편집에서만 일어나야 합니다. 읽기 시 쓰기(Read-Triggers-Write)는 금지입니다.

09

활성화·정리·의존성#

예제는 생성 API와 명령 해제 함수를 함께 반환합니다. 비활성화된 뒤의 오래된 API가 문서를 바꾸지 않도록 활성 상태를 확인합니다.

jsactivate / dispose
activate(context) {
  const creation = context.services.get('canvas.creation');
  if (!creation) throw new Error('canvas.creation 서비스가 필요합니다.');

  let active = true;
  const addNote = () => {
    if (!active) throw new Error('비활성화된 API입니다. 다시 조회하세요.');
    return creation.create({
      caller: addNoteCommand,
      aspects: { [aspectId]: { ...defaults } },
      width: 240,
      height: 160,
    });
  };

  const offCommand = context.commands.register({
    id: addNoteCommand,
    title: '스티키 노트 추가',
    summary: '현재 캔버스 중앙에 메모를 추가합니다.',
    shortcutScope: 'canvas',
    run: addNote,
  });

  return {
    api: Object.freeze({ addNote }),
    dispose() {
      if (!active) return;
      active = false;
      offCommand();
    },
  };
}

다른 확장과 연결하기

dependencies는 필요한 공급자를 먼저 켜고, optionalDependencies는 호환되는 공급자가 설치되어 있고 꺼져 있지 않을 때만 설치 순서에 참여합니다. 키는 npm 패키지명이 아니라 alid 논리 확장 ID이며, 선언만으로 다른 저장소를 다운로드하지 않습니다.

js공급자 API 조회
dependencies: { 'yourname.reading-notes': '^0.3.0' },
optionalDependencies: { 'sys.minibuffer': '^0.1.0' },

activate(context) {
  const minibuffer = context.getExtensionApi('sys.minibuffer'); // 없으면 undefined
  const notes = context.requireExtensionApi('yourname.reading-notes');
  // 선택 API는 호출 시마다 가용성을 확인하고 영구 캐시하지 않는다.
}

범위는 정확한 정식 버전·^·~·비교 연산자·와일드카드·공백 AND· || OR를 지원합니다. ^0.1.0은 0.1.x, ^0.0.1은 0.0.1만 허용합니다. 프리릴리스·빌드 접미사·하이픈 범위·축약 버전은 지원하지 않습니다. 직접 서비스를 제공하면 provides.services에 선언하고 context.services.provide()의 해제 함수를 정리 경로에 넣습니다.

watch 모드로 개발하기#

pnpm dev는 .alid-dev/에 watch 빌드를 만들고 로컬 서버를 엽니다. 기본 주소는 http://127.0.0.1:5174이며, alid의 확장 관리 → 개발 중인 확장 연결이 이 서버를 구독합니다.

경로 / 이벤트내용
GET /alid.extension.json마지막 성공 빌드의 설치 매니페스트(SHA-256 포함)
GET /dist/plugin.js매니페스트가 해시하는 번들. 매니페스트와 원자적으로 교체
GET /__alid/eventsSSE: hello, building, reload, build-error
  • 연결 범위 — localhost, 127.0.0.1만 연결할 수 있습니다. 서버도 127.0.0.1에서 열립니다.
  • 출처 — 기본 허용 출처는 http://127.0.0.1:5173, http://localhost:5173입니다. 다른 alid 출처는 pnpm dev --origin https://alid.example로 추가합니다.
  • 빌드 실패 — 마지막 성공 빌드가 계속 실행됩니다. 화면이 유지된다고 새 소스가 적용됐다고 판단하지 말고 빌드 번호와 오류를 확인합니다.
  • ID 고정 — 개발 중에는 확장 ID를 바꿀 수 없습니다. 바꿨다면 연결을 끊고 다시 연결합니다.
  • 저장 정책 — 개발 코드는 IndexedDB나 문서에 저장하지 않습니다. 새로고침하면 연결이 끊깁니다.
test:watch는 빌드하지 않습니다

test:watch의 plugin 테스트는 dist/plugin.js를 읽습니다. 최신 소스를 검증하려면 pnpm build 후 watch 테스트를 실행하거나 pnpm test를 사용하세요.

배포와 설치#

별도의 웹 호스팅이나 npm 배포는 필요하지 않습니다. 공개 GitHub 저장소의 기본 브랜치에 소스와 빌드 산출물을 커밋하면, 사용자가 alid의 확장 관리 → GitHub에서 설치에 owner/repo를 입력해 설치합니다.

sh배포
pnpm test          # 테스트가 빌드까지 수행한다
pnpm check:dist    # 커밋된 산출물이 최신인지 확인

git add -A
git commit -m "feat: add reading note tool"
git push origin main
  1. 커밋 고정

    호스트가 GitHub API로 기본 브랜치의 커밋 SHA를 조회합니다.

  2. 조회만, 실행 없음

    같은 커밋에서 매니페스트와 번들을 받아 경로·크기·메타데이터·SHA-256을 검증합니다.

  3. 명시적 신뢰

    사용자가 확인한 번들을 승인해야 런타임에 등록됩니다. 승인 전에는 코드를 실행하지 않습니다.

  4. 로컬 보관

    승인한 매니페스트·커밋·코드·사용 상태는 그 브라우저에 저장됩니다. 원격 최신 코드로 자동 변경하지 않습니다.

업데이트

같은 owner/repo를 다시 조회하고 새 커밋을 검토해 설치하면 업데이트됩니다. 기존 승인만으로 새 코드를 실행하지 않습니다. 기존 사용자에게 업데이트할 때는 id와 어스펙트 ID·속성 이름을 유지하고 version을 올립니다. 파괴적인 스키마 변경은 새 어스펙트 ID로 분리합니다.

번들 경계

설치 코드는 Blob URL에서 실행되므로 하나의 dist/plugin.js여야 합니다. 상대 경로 청크·별도 CSS·에셋·런타임 npm 설치에 의존하면 안 됩니다. 호스트 공유 모듈만 정확히 외부화합니다.

textvite.config.js 공유 모듈
@alid/kernel, @alid/react,
react, react/jsx-runtime, react/jsx-dev-runtime,
react-dom, react-dom/client

호스트의 커널·React를 중복 번들링하거나 내부 src 경로를 import하지 않습니다. 현재 예제는 SDK import가 필요 없습니다. React UI가 필요하면 공유 @alid/react와 호스트의 루트/포털 계약을 사용하고 별도 React 루트를 만들지 마세요.
